# 请求配置合并语义、同步异常兜底与去重取消交互修正

Status: accepted

## 背景

对 `createFetch` 的二次审查发现以下语义缺陷：

1. **配置深合并副作用**：`request()` 用 lodash `merge` 深合并基础配置与请求配置。`header` 深合并符合预期，但深合并波及 `successStatusCodes` 与 `data`——数组按索引合并（默认 `[200, 201]` + 请求 `[204]` 得 `[204, 201]`，201 残留仍算成功），`data` 若基础配置含之也会被递归合并而非整体覆盖。
2. **同步阶段抛错违反"永不 reject"契约**：`merge` 与去重 hash 计算（`stableStringify`）在返回 Promise 之前同步执行；`data` 含循环引用时 `stableStringify` 直接抛 `TypeError`，`request()` 同步 throw，调用方无 try/catch 即崩溃，与错误归一化契约（ADR 0001）相悖。
3. **去重等待者的 abort 静默失效**：被去重合并的第 2+ 个调用者尚未注册内层 cancelable，`abort(key)` 找不到监听者而无效，等待者仍收到共享结果。
4. **`rejected` 恢复值绕过运行时校验**：响应拦截器 `fulfilled` 返回值有 `isResponseResultLike` 校验（ADR 0002 §5），但 `rejected` 恢复值与请求拦截器恢复值直接透传，非法值沿链路扩散。

## 决策

### 1. 合并语义：`header` 深合并，其余字段浅覆盖

`header` 维持深合并（基础头与请求头按字段叠加）；`successStatusCodes`、`data` 等其余字段浅覆盖——请求配置提供即整体替换（数组按引用替换，不做索引合并）。合并仅作用于请求配置与基础配置之间，不改变 `rawRequestConfig` 保留原始引用的行为。

### 2. 同步阶段兜底：merge 与去重 hash 包 try/catch

`request()` 内配置合并与 hash 计算（含 `stableStringify` 同步抛错）统一包入 try/catch，任何同步异常归一化为 `code: -4` 失败结果返回，契约扩展为"永不 reject 且永不同步 throw"。注意：`isDedup` 为 false 时不计算 hash，同步兜底主要防护合并阶段异常。

### 3. 去重取消：abort 按 key 广播，共享执行（传输层）不中断

`isDedup` 开启时，共享执行（第一个调用者执行的 `core`）以剥离用户 key 的方式运行，传输层不注册用户取消监听；每个调用者（含去重等待者）都用自身 key 包裹各自的等待。`abort(key)` 按 key 广播：同一去重组（共享相同 key）的所有调用者均收到 `code: -1` 中止结果，共享执行（传输层）不因取消而中断、继续完成（其结果被丢弃）。

这取代了 ADR 0002 §6 的既有语义（该语义下 `abort(userKey)` 会取消第一个调用者的传输层执行）；现在无论第一个调用者还是等待者取消，共享执行都不中断，所有共享该 key 的调用者统一收到 `-1`。

### 4. `rejected` 恢复值运行时校验

拦截器 `rejected` 返回 truthy 恢复值时，与 `fulfilled` 路径一致做运行时校验（响应拦截器校验 `isResponseResultLike`，请求拦截器校验配置形状），非法则 `console.warn` 提示并忽略、沿用上一值，避免类型谎言沿链路扩散。

### 5. 明确不改

- 去重键维持全量合并配置 hash（含 `key` 与 `rawRequestConfig`）——现状即预期，相同请求带不同 key 不去重属既定行为；
- 拦截器错误统一 `-4` 不区分业务 throw 与编程错误，`error` 字段保留原始异常供调试；
- 不提供拦截器 `eject`。

## 后果

- 合并语义可预期：数组配置提供即替换，`data` 不再被意外递归合并；`header` 叠加行为不变。
- 永不 reject 契约扩展到同步阶段，`request()` 不再可能同步 throw。
- 去重与取消的交互语义完整：`abort(key)` 按 key 广播，同 key 的调用者（含等待者）统一收到 `-1`；共享执行（传输层）永不因用户取消而中断。
- 拦截器两条路径校验一致，非法恢复值不再污染后续链路。

## 被驳回的替代方案

- **完全浅合并（含 header）**：丢失基础头叠加能力，调用方需每次完整传头。
- **同步阶段不兜底、仅文档化**：契约仍存在硬伤，调用方无法防同步 throw。
- **等待者 abort 仅取消自身、共享执行继续且其余等待者仍收共享结果**：与 `abort(key)` 按 key 广播的既有机制冲突，需引入按调用者维度的取消 token，超出本次范围；统一为广播取消。
- **`rejected` 恢复值照用不校验**：类型谎言继续扩散，与 ADR 0002 §5 的校验目的相悖。
